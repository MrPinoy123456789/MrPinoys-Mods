## 1. Rules that always apply

- **Punctuation:** never write an em dash or a double hyphen as punctuation, anywhere (code comments, lang strings,
  docs, commit messages, chat). Use a colon, semicolon, comma, parentheses or a new sentence. Command flags such as
  `--dry` and operators such as `i--` are fine. Check with
  `grep -rn -e $'—' -e ' -- ' --include='*.java' --include='*.md' --include='*.json' <dir>`.
- **Git identity:** commit and push as `MrPinoy123456789` with the noreply email, per command
  (`git -c user.name=MrPinoy123456789 -c user.email=MrPinoy123456789@users.noreply.github.com commit ...`). Never author
  as `krisean`. Remote is `https://github.com/MrPinoy123456789/MrPinoys-Mods` (credential helper through `gh`).
- **Branches:** work on a named `feature/<topic>` branch off `master` (there is no `main`). Rename placeholder
  `claude/*` branches to something descriptive. Commit before another session shares the tree. The workspace root
  checkout stays on `master`; use `git worktree add -b feature/x .claude/worktrees/x master` for new work.
- **Deploys and restarts are the owner's call.** "Implement" never means "deploy". Get a clear yes in chat, check who is
  online, and warn players. Never print or commit credentials (`tools/playtest/kinetic.env`, bot tokens in
  `config/charter/discord.json`).
- **Owner preferences:** player choices use in-world objects or the Charter book, not typed commands (half the players
  are Bedrock on Xbox and cannot type). Film and pop culture jokes on buttons and flavour text are welcome, never on
  error messages. Report faithfully: say what is unverified. Keep answers short and plain.
- **Line endings:** many files are CRLF. Check a file's endings before editing and keep them. Several Python edit
  scripts in the scratch folders use `newline=''` for this reason.

## 4. Building and testing (this machine)

- Charter: `cd charter && ./gradlew.bat build --no-daemon --console=plain` (about 2 minutes). Core tests (`CoreSuite`),
  fabric tests (`FabricSuite`), and gametests (`runGameTest`). New gametest classes must be listed in
  `charter/fabric/src/gametest/resources/fabric.mod.json` or they never run; check the test count rises.
- Foundry: `cd foundry && ./gradlew.bat build` (about 1 minute, has gametests). Currency: `cd chartercurrency && ./gradlew.bat build`.
- Pocket Dungeons: `cd pocketdungeons && bash tools/ship.sh --quick` (about 5 minutes, writes the jar to `dist/`). Options:
  `--pure`, `--only <GameTestClass>`, `--no-dist`. Full log: `A:/tmp/ship-<worktree name>.log`.
- **Memory:** the machine runs out of memory under load. For Charter, Foundry and currency use
  `export JAVA_TOOL_OPTIONS="-Xmx1200m"` and `--no-daemon`. For Pocket Dungeons use
  `export GRADLE_OPTS=-Dorg.gradle.daemon=false JAVA_TOOL_OPTIONS=-Xmx1200m`. **Do not use a heap below 1200m or
  `-XX:+UseSerialGC` with Pocket Dungeons**: its test JVM then spins at 100 percent CPU forever (this cost hours).
  Never run two Gradle builds in the same folder at once (they share one log and lock). If a gametest JVM spins with
  no output, stop that one `java.exe` (check its command line first, never touch the `javaw.exe` Minecraft launcher).
- Known flaky test: Pocket Dungeons `HauntFloorGameTest` (`the_keeper_stalks_and_the_beacons_hold_the_pad`) and
  occasionally Heist; rerun it alone with `bash tools/ship.sh --only HauntFloorGameTest`.
- Checks in the gametest harness: `LandKit` turns `requireAffiliation` off for land tests; Charter entity queries need
  `level.waitForEntities` (see `CLAUDE.md`).

## 7. Things that bit us (read before touching these areas)

- Geyser (Bedrock) cannot translate Polymer `item_display` entities; skip Bedrock viewers (Floodgate UUID MSB == 0).
- A server pack is optional and cached by hash. If a model looks old, check the hash in
  `.minecraft/server-resource-packs/` against the server's `/polymer/resource_pack.zip` SHA-1.
- Polymer `ElementHolder`/attachments are not sent to the wearer by vanilla (a player never gets their own entity);
  the wearer must be shown the holder explicitly.
- Textures referenced by item models must live under `textures/item/` or `textures/block/` (or be added to an atlas).
- A written book cannot run commands on Bedrock; the Charter book is dialogs and, with the new work, native forms.
- Vanilla opens the jigsaw editor on the client for ops in creative whatever the server returns; hence the bedrock
  lookalike.
- `Heightmap` and chunk queries inside load events, gametest entity counts and mock players sharing a scoreboard name
  are covered in `CLAUDE.md` and the skills under `.claude/skills/`.
- The Axiom mod is disabled; its saved game rules (`axiom:*`) fail to parse on every start (harmless noise unless the
  owner re-enables Axiom). `players_sleeping_percentage` is 1 (one sleeper skips the night).
- Do not delete the hand built cobble walls around Azrak, Aurelia, Azurius and Everdelle (owner choice).
- The auto mode permission classifier blocks production deploys and process kills unless the owner has just said yes in
  chat for that specific action; ask, then retry once, never work around it.
