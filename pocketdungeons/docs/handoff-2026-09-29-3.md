## Player-driven fixes

1. **PD-90, `room_bias` UX.** The player asked for four things after watching
   a bias take ~2 minutes while the MCP was mid-restart:
   - Lock him out of starting the next run while a bias is being set up (a
     flag the door/commit path checks, or hold the preview/commit while set).
   - Apply faster (the server-side part is instant; this was harness latency,
     but make the apply path report success back to the player).
   - A timeout so a stuck agent cannot leave him waiting.
   - The sign above the doors should list active biases (find the staging
     room sign/screen code, likely `DungeonScreen` or the staging spec).

2. **PD-89, crafted diamond gear bypasses the durability economy.** A crafted
   diamond sword lasted several floors nearly unworn, while dungeon drops are
   tuned to burn out in one. Decide the ceiling: make crafted gear inside the
   dungeon similarly short-lived, tax crafting results, or accept the leak.
   IMPORTANT counterpoint from the same session: his diamond armour "broke
   VERY quickly", probably combat. Armour drains a point per hit taken, so
   before touching numbers check whether both observations are just vanilla
   wear rates; the mod may only need to not make it worse.

3. **Thicket tuning (post-PD-86).** Now that the spawner fires, the room is
   "pretty difficult". Two asks:
   - Sparser webs: the decor is already a 3D checkerboard
     (`TraversalSpecs.java` thicket `.decor`, `(x+y+z)%2`). He wants roughly
     half again, "a kind of lattice". Try a period-3 or sparser pattern.
   - Spawner counterplay: a light source touching one of the classic
     spawner's faces should disable it (the classic mechanic he expects).
     `ClassicSpawners` custom spawn rules currently allow spawn at any light;
     a face-check for an adjacent bright block in the spawner tick or a
     light-based custom rule would give the counterplay. Regenerate
     `thicket.nbt` if the web pattern changes.
