## Bugs to fix

1. **PD-85, door preview glass blocked by the doors.** The preview window sits
   in the wall directly behind the selector doors, so a closed door covers the
   glass and the player cannot see into the previewed room. Find the staging
   room selector construction and the window code (search `window`, `preview`,
   `WindowPreview`, `Instances.windowPreview`). Move the glass off the door
   row (above the doors, or a dedicated segment) and make sure no wall blocks
   the sight line from the glass into the room either.

2. **PD-86, `thicket` spawner never fires.** `TraversalSpecs.java` registers
   the thicket with a classic spawner at (8,1,8) configured to cave spiders by
   `ClassicSpawners.configure` (custom spawn rules 0..15 for light). Player
   stood in the room ~3 min and saw nothing. Verify first: stamp a thicket on
   a test slot (`/dungeon admin` tooling) and `/data get` the spawner's block
   entity; confirm the block exists, its SpawnData id is cave_spider, and the
   custom rules took. Suspects: template lacks the spawner block, the block is
   not `minecraft:spawner`, spawn placement fails inside the cobweb
   checkerboard, or `BaseSpawner.load` drops the rewritten SpawnData.

3. **PD-87, non-stacking trial key.** Player has a `minecraft:trial_key` that
   does not stack with other keys and "doesn't work". Find every place a trial
   key is created or checked (vault `keytag`, chest loot tables, mob drops,
   `RoomContent`, vault config writes). Make issued keys bare identical items
   and make sure whatever consumes them accepts them. Regression test: two
   keys from different sources stack.

4. **PD-88, explosive hazard fully legible.** `RoomContent.java`
   `placeExplosiveHazards` puts the pressure plate on a stone support beside
   the TNT so the plate survives ignition; the visible spacer makes the trap
   impossible to trip by accident. Keep the survive-the-blast property but
   make the hazard able to catch a careless step (plate flush with the floor,
   support hidden, or a different trigger). Player also suggested scattered
   floor obstructions as general room texture; if cheap, add a light
   obstruction scatter to the decor pass, otherwise note it for later.

5. **Hold-the-plate redesign (player proposal, replace the early-complete
   fix).** Current: `HoldThePlateHandler` completes the hold early when the
   room's spawners are cleared; the player says that "makes standing on it
   pointless." His proposal: decouple the fight from the trial spawner. When
   the player steps on the plate, spawn a mob immediately, then spawn more at
   timer milestones with difficulty ramping toward the end. The hold itself
   is the fight; pre-clearing the room no longer skips anything. Implement in
   `HoldThePlateHandler` (or wherever the 30 s timer lives): mob spawns keyed
   to remaining time, likely reusing the room's mob table. Decide whether the
   existing early-complete stays as a fallback when the player already
   stepped on it once.

## Design items (proposal, not code, if large)

6. **Home cannot grow a tree.** The safe room interior is ~6 blocks high
   (`RoomGeometry.WALL_HEIGHT` 5), vanilla trees need 7+. The player tried to
   plant one. Either give the home/safe room more headroom (it is a
   pseudo-room, see `FloorRooms.SAFE_ROOM` / `Instances` stamping, not a
   normal cell) or intentionally add a taller variant.

7. **Bows are disposable.** "So many bows are dropping and a normal amount of
   arrows": bow drop rate makes Unbreaking dead value and Power strictly
   better. Retune bow drop frequency or arrow supply in the loot tables;
   check `LootTables.java` and the chest loot json.

8. **No vertical challenges, so blocks are useless.** Design note for the room
   pass: nothing requires climbing, so stone/cobble/brick drops are dead
   weight. A traversal room with a climbable problem (or blocks-with-a-job
   like bridged gaps) would give them a purpose. Proposal only.

9. **Lemon steers generation (playtest harness idea).** The player suggested
   Lemon bias dungeon generation toward rooms under test. If feasible, add a
   plan/room weight hook the agent can set via the server tooling; otherwise
   write a short proposal.

## Harness fixes (tools)

10. **PD-80 still open.** `tools/server/pdserver.mjs` `wait` printed
    `server is down (timeout)` twice more while the server was up. Apply the
    noted fix: require two consecutive failed `isUp` checks, or re-check once
    at timeout before printing.

11. **llm mode lapses when the agent stops waiting.** The lemon mode refresh
    rides on the `wait` loop; pausing the loop (to investigate) expired llm
    mode and one player question hit the guide fallback instantly
    (`answered_by none, wait_s 0`). Decouple the refresh from `wait` (own
    timer in the MCP server or a keepalive the server side owns) so questions
    are never silently downgraded.
