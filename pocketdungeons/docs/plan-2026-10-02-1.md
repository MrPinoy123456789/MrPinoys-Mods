## Wave 1: bugs (PD-105 to PD-112)

### PD-106 and PD-108 share a root cause: vanilla trial chamber equipment

Findings from the pre-plan investigation (verify, then fix):

- Five spawner configs equip mobs from **vanilla** tables
  `minecraft:equipment/trial_chamber_melee` and `..._ranged`:
  `trial_spawner/{copper_works,crypt,frostworks,ossuary}_tier_3/*` and
  `trial_spawner/tier_3/*`. Vanilla's trial chamber equipment is full
  **trimmed** armour (iron, chainmail, diamond).
- `DungeonDrops.java` raises every dungeon mob's per-slot drop chance to at
  least `EQUIPMENT_DROP_CHANCE = 0.2f` (bows 0.05). Four armour slots at 0.2
  each means a tier 3 room rains trimmed armour.
- `SalvageStation.classify` (around line 102) refuses anything with
  `DataComponents.TRIM` ("trimmed"). So the diamond leggings in PD-108 were
  almost certainly trimmed trial chamber leggings. Confirm by reading the
  journal/log for the refusal reason if available.
- Also: `trial_spawner/the_raid/*` references `pocketdungeons:equipment/tier_3_melee`,
  which **does not exist** (only tier_1 and tier_2 files are in
  `loot_table/equipment/`). Fix this too.

Fix:

1. Add `loot_table/equipment/tier_3_melee.json`, `tier_3_ranged.json` (and
   `tier_3_armor.json` if the tier_2 files reference an armour table; mirror
   the tier_2 structure). Untrimmed, with a large `minecraft:empty` weight per
   armour slot like tier_2 (45 to 55 empty). At most a small, explicit chance
   of one trimmed piece if the owner wants trims to stay findable; trims also
   come from chest and vault tables already.
2. Point the five tier_3 spawner configs and `the_raid` at the new tables. No
   spawner config should reference `minecraft:equipment/trial_chamber_*`.
3. In `DungeonDrops`, keep the 0.2 floor for weapons but give armour slots a
   lower floor (start at 0.08, roughly vanilla). Name it
   `ARMOUR_DROP_CHANCE` with a comment citing PD-106 and this playtest.
4. Salvage (PD-108): trimmed gear is refused on purpose ("keep-safe" order in
   the javadoc). Keep the refusal, but make it legible: the refusal text the
   player sees must say why ("Trimmed pieces are kept safe. Remove the trim at
   a smithing table first" or similar) and the bench screen should show it.
   Also check the other refusals (`goes home with you`, imbued, Cube reward,
   `not gear`) for the same readability. If a non-trimmed diamond legging is
   refused anywhere, that is a real bug; add a gametest that a plain
   `diamond_leggings` classifies as `MOB_GEAR` or `GEAR`.
5. Gametests: every `trial_spawner/**.json` equipment table id resolves; no
   config uses `minecraft:equipment/trial_chamber_*`; classify verdicts for
   plain, trimmed and tier-tagged leggings.

### PD-107: mixed mob pools

Findings: the generic fallback configs are broad. `trial_spawner/tier_3/normal.json`
alone spawns bogged, breeze, cave spider, husk, pillager, skeleton, spider,
stray, vindicator, wither skeleton and zombie; `tier_2` spawns six types.
`TrialContent.configId` (around line 436) falls back to plain `tier_N` when a
theme has no `spawner_prefix` (see `dungeon_theme/*.json`) and rooms may also
carry their own config.

Fix now (small): split the generic pools so each config is two related mob
types at most (zombie + husk, skeleton + stray, spider + cave spider, etc.),
and make the generic fallback pick one of those narrow configs per spawner
(seeded from the plan, so it is stable). Keep the current broad pool as a
rare explicit `chaotic` config (start at 5 percent, a config value). Find
which themes and rooms hit the generic fallback and list them in the commit
message. The full theme redesign is item 11 (Wave 4): do not go further here.

### PD-105: Lemon's journal can be taken

`LemonBody.java` already overrides `interact` (main hand opens the menu,
everything else `FAIL`) and `mobInteract` (`PASS`). So the code path that
hands over the book is somewhere else. Reproduce before fixing:

- Write a gametest that spawns a `LemonBody` holding the book, has a mock
  player with an empty hand interact in both hands (and `interactAt`), and
  asserts Lemon still holds the book and the player inventory is unchanged.
- Candidates to check: vanilla `Allay` paths that bypass `interact`
  (`interactAt`, `Allay` item hand-off goals, `dropEquipment` when the body is
  discarded or moved to a "fresh spot" by `Lemon`), and whether the
  lodestone menu itself (`RitualListener.openMenu`, `DialogScreens` section 11)
  shows a book stack that can be clicked out. Ask the owner what "she gave me
  the book" looked like only if the test and code read do not find it.
- Fix the actual path; the test must fail before and pass after.

### PD-109: tripwire hall traps clipped

`MechanismSpecs.tripwireHall()` (around line 454) places the hooks and string;
`dungeon_room/tripwire_hall.json` uses template `rooms/tripwire_hall`. Check
the hook x/z against the shell pass (`BedrockEnvelope`, `RoomGeometry` wall
thickness) at every rotation. Move the assembly inward by one block (or narrow
the walkable area as the player suggested) so no hook, string or dispenser is
on a shell coordinate. Recapture the template if the room uses one. Gametest:
after stamping at all four rotations, every hook, string and dispenser the
spec placed is still present.

### PD-111: spawner gate message

### PD-112: sensor omen sound

### 18. Dead-end fountain boon

empties. One use per party. Hook interaction through `RitualListener.onUseBlock`
like the other stations. Gametest: chance roll is seeded, the boon applies,

### 10. Mending as a paid "lock in"

Facts: no loot table names Mending directly, so it arrives via random
enchant functions that allow treasure, or via vanilla tables;
`RerollStation.java` (line 162) deliberately leaves Mending reachable as a
reroll result. Plan:

- Remove Mending from all random sources: loot `enchant_randomly` /
  `enchant_with_levels` options (use an enchantment tag that excludes it), and
  the RerollStation pool.
- New station action "Lock in": pay a large cost, the item gains Mending and a
  `pocketdungeons:locked` custom data flag.
- Questions for the owner: which station hosts it (Reroll, Salvage, or the
  blacksmith)? Cost (lapis, emeralds, echo shards)? Recommendation: locked
  items are refused by Salvage and by Reroll (locking is the end of the
  gear's journey), shown in lore as "Locked in".
