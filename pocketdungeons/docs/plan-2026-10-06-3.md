## Rules for every step

- **Pure first.** Put every new rule in a class with no Minecraft imports so a
  plain `javac` check works (plan 1 shows the recipe), then wire it in.
- **Tests with the code.** Each step names its tests in plan 2. Write them in
  the same commit. Register new gametest classes in
  `src/gametest/resources/fabric.mod.json`; confirm the count rose.
- **Before each commit:** `./gradlew test`, then
  the dash grep given in `../CLAUDE.md` from the workspace root, and fix
  anything you wrote. (Existing `--` in older javadoc
  is left alone unless that line is being edited.)
- **Docs move with the code.** Each plan 2 section lists the design doc
  amendments (`DUNGEON_STRUCTURE_DESIGN.md` D8, D11, D12, D13, D14, D16, D16a;
  `ORDEALS.md` rubble; `BUGS.md` entries). Make them in the step's commit.
- **Old saves.** No migration code. New `DungeonLog.Entry` fields take defaults;
  superseded fields keep their codec entries.
- **When a step lands**, put its commit hash in the "State" column above and in
  plan 2's "Order of work" table.
