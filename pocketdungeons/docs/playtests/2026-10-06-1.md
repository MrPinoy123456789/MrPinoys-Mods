# Playtest 2026-10-06-1: chart scrap build (Kinetic test server 714a0605)

Live session, Lemon interviewer (operator agent), first live run of the chart
scrap / compass / new door board build (deployed this session).

Player: MrPinoy123456789, compass 11 to 12, solo.

## Summary

- Server times about 04:30 to 05:51. Three trips seen: Infestation floors 1-2
  banked at 04:53 (5 scrap = 1 chart, levels_gained 1), an Ossuary trip with the
  flooded_hall iron door report, then a full Mineshaft clear (3 floors, first
  finish, diary entry 8, banked 0 charts because resource floors pay none).
- Almost every Lemon contact was volunteered design feedback or a bug report.
  He wrapped the session himself and took two closing questions.
- Top three findings:
  1. PD-149 is not fixed in the wild: Mineshaft floor 1 rolled all generic
     halls, `nodes_total` 0 again. Floor 2 of the same trip did get
     `mineshaft_seam` (nodes 5/8 mined on floor 3). The guarantee is partial.
  2. Interior mining is a hit. On the seam room: "This room I'm in is one of
     my favourites so far. ... It feels like minecraft." He also reasoned the
     mechanic is self-balancing: "The durability of the tools balances the
     abundance of cobblestone."
  3. The door board still has a real flaw: identical doors. He rejected the
     "Same as door n" label: "if they are the same then they should have
     different affixes." New rule: no truly identical doors; reroll affixes.

## Bugs

- PD-149 reopened (High). Mineshaft floor 1, run starting ~04:58, rooms were
  entrance/corner/tee/dead_end/exit/ominous_bargain only, `nodes_total` 0.
  `ensureResourceRooms` either did not fire or found no eligible cell. Needs a
  seed-level repro; the 40-seed unit test passes, so look at what differs live
  (party size, act, or the eligible-cell check).
- PD-157: Diary books clip long pages (Medium). Entry 8 "The First Pick" shows
  only its first page-worth of text. Each authored `pages[]` entry becomes one
  verbatim book page; written-book pages clip at about 14 rendered lines.
  Rough estimate flags about a dozen authored pages across the set as over the
  limit. Fix: paginate text into real book pages at book build time
  (`DiaryDelivery.book`).
- PD-158: Omen bar does not track interval omen (Medium). Player: "My omen was
  4/4 but the bar wasn't full, it didn't seem to progress properly with deaths
  and eating." Journal shows interval omen reached 4 on the floor; the bar's
  denominator/fill may key off the wrong value (`OmenBar`/`OmenBarText`).
- PD-159: Store left-click can consume stock without delivering (High).
  "If I left click an item in the shop, I don't get the item sometimes and it
  runs out of stock." Same session's earlier report: a bought oak log kept the
  listing's name/lore and would not stack. Likely cause already located:
  `StoreNPC.sell` delivers `current.stack()` without `cleanResult`; left-click
  path probably decrements stock without a successful vanilla `onTrade`.
- PD-160: Iron door connector with no reachable opener (High). Flooded room
  (`flooded_hall`) behind an iron door connector; player could not break the
  door and had no placeable redstone within reach. PD-55's attached-lever fix
  apparently did not cover this configuration. Reconcile with PD-27/PD-55.

## Design decisions taken (owner, in session)

- No identical doors, ever. Drop "Same as door n"; reroll affixes until doors
  differ (PD-153 superseded).
- Resource dungeons pay chart scrap like any other floor, gated only by the
  underlevel rule. (Noted: currently impossible to outlevel solo since floor
  level = compass + step; underleveling only bites for overleveled party
  members. Authored fixed floor levels would make it real; flagged.)
- Run storage should become a player-managed chest-like inventory ("store
  stuff in the run storage like it's an enderchest"), replacing the
  auto-return-to-pack model.
- Player suggestion, cheap: hide ore pockets inside interior walls so mining
  the dressing can reveal nodes.
- Board requests pending implementation: floor count on its own line, non-title
  text about 20% smaller, resource names simplified (say "gold ore", not both
  "deepslate gold ore" and "gold ore").
- Post-session board decisions (owner, in chat): scrap count must be visible
  mid-run, he only ever knew his chart total. Final spec settled:
  door board is `DUNGEON · floor N of M` / `Floor name · affixes` /
  `3 scrap · 2 echo shards` (cyan, no "Rewards:"/"Resources:" labels, resource
  names simplified and deduped) / `loot ×3 · 2 echo shards` (roll count green,
  cost yellow). No "Same as door n" (superseded PD-153). Scrap visibility
  lives on the GO HOME board, not every door: `carried: 7 scrap` plus
  `take home: 1 chart · 2 scrap stays`. `loot ×3` counts the floor's
  completion rolls (`Omen.baseRewardChests()` + depth bonus).
- Balance note: diamond pickaxe durability too low (his was max 20).

## Confirmed working live

  `scrap_left` 0, message understood when asked ("carrying 5 scrap" answer
  matched his count).
- Reward containers: barrel + copper chest approved ("Yes, it's good").

  silenced affix's eat block. His read: "Cake is valuable because I can eat it
  off the ground avoiding silence." Worth keeping; a clever workaround.
