## Harness notes

- **MCP over HTTP works for a local Devin.** `mcp.mjs --http 8787 --admin` plus curl JSON-RPC did the whole session: initialize, `knowledge_pack`, `sync`, `wait_events`, `lemon_say`, `lemon_reply`, `lemon_mode`. No tunnel needed since Devin Desktop runs on the same machine; worth noting in `tools/lemon/README.md` that the HTTP path also suits a local agent without stdio.
- **`wait_events` does not surface `door_commit`, `enter_dungeon` or `quit_floor`.** They are not in the event kinds, so the quit penalty was only visible via the playtest journal (`summarize.mjs`). An agent driving only `wait` would report "nothing happened" between join and leave. Consider adding them to the feed or pointing agents at the journal mid-session.
- **PD-80 not exercised:** both `wait_events` calls returned on real events within seconds, so the false "server is down" message never had a chance to appear.
- **`quit_floor` penalty field came from `timedOutDepletion` at call time** (`RunLifecycle.java:1991`), so the journal faithfully recorded the misconfiguration rather than the intended cost.
- **Agent-side gaps still miss asks.** The 19:19:41 `lemon ask` arrived while I was investigating PD-82 with no `wait_events` call in flight; by the time the next wait returned it (batched with the `floor` and `unanswered` lines), the 45 s fallback had fired. `wait` correctly held it (PD-79 stays fixed); the lesson is to keep a wait outstanding at all times during a session.
